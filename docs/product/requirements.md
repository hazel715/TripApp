# 제품 요구사항

범위 경계는 [scope.md](./scope.md), 화면 흐름은 [user-flows.md](./user-flows.md).

## 문제

여러 사람이 특정 목적(장보기, 여행, 회식, 캠핑, 공동생활비)으로 돈을 쓰고, 누가 냈는지와 누가 부담하는지가 다르다. 통화가 섞이면 머리로 정산하기 어렵다.

레거시는 청두 여행 1건 + 멤버 3명에 고정되어 있다.

## 목표

사용자는 Project를 만들고, 멤버를 넣고, 지출을 기록하고, 기준 통화 기준 정산 송금 목록을 받는다.

## 사용자

- **참여자**: Project에 속한 사람. 지출을 넣거나 조회하고 정산을 본다.
- **생성자/관리자**: Project 설정(이름, 기준 통화, 멤버, 카테고리)을 바꾼다.

레거시에는 역할이 없다. 익명 로그인 + 공개 문서 1개다. 신규 1차에서는 “멤버는 모두 읽기/쓰기, 삭제/설정은 생성자”를 기본으로 한다. 세분 권한은 [아직 결정할 사항](#아직-결정할-사항).

## 기능 요구사항

### Project

- Project를 생성·이름 변경·보관(archive)·삭제할 수 있다.
- Project마다 멤버, 지출, 정산이 독립이다.
- Project마다 **기준 통화**를 가진다. 기본값 KRW.

### Member

- Project에 멤버를 추가·제거할 수 있다.
- 표시 이름(닉네임)을 가진다.
- 이미 지출/정산에 등장한 멤버는 하드 삭제 대신 비활성 처리한다. 규칙: [../data/data-rules.md](../data/data-rules.md).

### Expense

최소 개념:

- 소속 Project
- 지출 일자 (날짜만, 시간 없음)
- 설명(제목)
- 금액 + 통화
- 결제자 1명
- 참여자 1명 이상
- 참여자별 부담 금액
- 카테고리
- 메모(선택)

1차 분배 방식은 레거시와 같이 **참여자 균등 분할**을 기본으로 한다. 불균등 분배는 ExpenseShare로 확장 가능하게 모델링한다. 상세: [../domain/expense.md](../domain/expense.md).

### Currency / ExchangeRate

- 지원 통화 최소: KRW, CNY, USD (레거시와 동일). 추가는 코드 테이블.
- 지출 저장 시 사용한 환율을 **그 지출에 고정**한다 (레거시 `exchangeRate` + `customRate`와 동일 의도).
- 기본 환율은 Project 설정 또는 전역 기본값에서 온다. 실시간 API는 2차. 상세: [../domain/exchange-rate.md](../domain/exchange-rate.md).

### Settlement

- 모든 미정산 지출을 기준 통화로 환산한 뒤 순잔액을 계산한다.
- 채무자 → 채권자 송금 목록을 만든다.
- 송금 횟수는 실용적으로 최소화한다 (레거시 greedy). 완전 최적해는 요구하지 않는다.
- 정산 실행을 저장할 수 있다 (레거시는 계산만 하고 저장하지 않음). 상세: [../domain/settlement.md](../domain/settlement.md).

### 날짜

- 저장: `DATE` (지출일), `timestamptz` (생성/수정).
- 표시: `MM-DD` 또는 `M월 D일` 등 UI 포맷. 저장과 분리.
- 연도 없는 문자열 저장을 금지한다.

### 비기능

- 계산 결과는 테스트로 고정한다. [../testing/test-strategy.md](../testing/test-strategy.md)
- 금액은 부동소수점으로 누적 정산하지 않는다. [../calculation/rounding-rules.md](../calculation/rounding-rules.md)
- 레거시 Firebase API 키를 신규 코드에 복사하지 않는다.

## 명시적으로 요구하지 않는 것 (요약)

여행 일정, 지도, 숙소, 준비물 체크리스트. 전체 목록: [scope.md](./scope.md).

## 아직 결정할 사항

제품 결정이 필요한 항목은 이 문서에만 모은다. 구현 전에 확정한다.

1. **불균등 분배 1차 포함 여부** — 레거시는 N빵만 있다.
2. **정산 단위** — 전체 미정산 일괄 vs 기간/선택 지출.
3. **정산 완료 후 지출 수정 허용 여부**.
4. **실시간 환율 API** — 1차 수동/기본값 vs 조회.
5. **로그인** — 이메일, 소셜, 초대 링크만.
6. **오프라인/실시간 동기화** — 레거시 Firestore `onSnapshot` 수준을 1차에 넣을지.
7. **기존 청두 지출 데이터 이관 여부**.
8. **카테고리** — 전역 고정 vs Project별.
9. **기준 통화가 KRW가 아닌 Project** — 1차에서 허용할지.
10. **수수료** — 환전 수수료를 환율에 포함할지. 레거시는 없음.
