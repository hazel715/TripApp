# 사용자 흐름

화면 구성은 [../frontend/screens.md](../frontend/screens.md). 이 문서는 행위 순서만 적는다.

## 1. Project 시작

1. 로그인한다.
2. Project 목록에서 만들기를 누른다.
3. 이름, 기준 통화(MVP: KRW), 초기 멤버를 넣는다.
4. Project 홈으로 들어간다.

## 2. 지출 기록 (상세 폼)

레거시 `handleOpenExpenseModal` / `saveExpense`와 같은 순서.

1. 가계부에서 추가를 누른다.
2. 결제자, 카테고리, 일자(date picker), 제목, 금액, 통화를 넣는다.
3. 통화가 기준 통화가 아니면 기본 환율이 채워진다. 필요하면 직접 입력한다.
4. 참여자를 토글한다. 최소 1명. 결제자가 참여자에 없어도 된다 (레거시도 가능).
5. 미리보기로 기준 통화 환산액과 1인 부담(균등)을 본다.
6. 저장한다.

검증: 제목·금액 필수. 레거시는 `title`과 `amount`만 검사한다. 신규는 일자·결제자·참여자도 필수.

## 3. 퀵메모 지출

레거시 `saveQuickMemo`.

1. 한 줄 텍스트를 넣는다. 예: `mj 훠궈 300`, `혜진 $10 택시`, `jy 3만원 간식`.
2. 파서가 결제자·통화·금액·제목을 추출한다.
3. 일자는 오늘, 카테고리는 기타, 참여자는 전원, 환율은 기본값.
4. 저장 후 목록에 보인다. 사용자는 상세 폼으로 고칠 수 있다.

파서 규칙은 [../legacy/reusable-logic.md](../legacy/reusable-logic.md). 서버 또는 `ledger-core`에서 파싱하고 UI는 결과만 보여 준다.

## 4. 목록 조회

1. 그룹 기준을 일자 / 결제자 / 카테고리 중 고른다.
2. 그룹 합계와 전체 합계는 **기준 통화 환산액**이다.
3. 행을 누르면 수정한다.
4. 삭제 전 확인 모달을 쓴다.

## 5. 정산

1. 정산하기를 누른다.
2. 서버(또는 core)가 미정산 지출로 잔액과 송금 목록을 계산한다.
3. 사용자는 표(결제액/실부담/정산액)와 송금 가이드를 본다.
4. MVP: “정산 확정”을 누르면 Settlement가 저장되고 해당 지출이 묶인다.
5. 이후 새 지출만 다음 정산에 들어간다.

레거시는 4–5가 없다. 매번 전체 지출을 다시 계산한다.

## 6. 멤버 변경

1. 설정에서 멤버를 추가한다.
2. 기존 지출의 `included`는 자동 변경하지 않는다.
3. 제거는 비활성. 과거 지출의 결제자/참여자 표시는 유지한다.
